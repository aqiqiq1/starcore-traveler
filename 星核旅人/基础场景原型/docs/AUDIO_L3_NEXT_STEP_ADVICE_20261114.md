# 音效、第三关布局与后续整体优化建议

日期：2026-11-14。**本文件是下一阶段提案，不代表音效或第三关已经实现，也不自动授权修改现有玩法。** 当前轮次的提示精简/全关门效属于另一个已授权的小优化，实际结果见`GATE_TEXT_CLEANUP_20261114.md`。

**后续讨论更新：第6节记录创作者新增的限时浮地/守卫核心方向，并明确选择低容错的“异相吸近→切同相顶斥力攻击”。它覆盖下文旧初稿的可绕过守卫/可选J及原五段空间安排；具体数值与完整布局尚未原型验证。**

## 1. 建议先确定的方向

第三关的核心体验是：**终于望见城门 → 自己打通一段路线 → 空手熟练借力 → 应对守门者 → 亲自走进城中。** 不再重复整关运核教学，不扩成战斗关，也不临时引入新能力。

沿用已确认边界：
- Demo只讲断桥到入城，第三关必须在实际入城后结束，不能在门外用字幕代替。
- 第三关有效体量不低于第一关；地图长度只是灰盒起点，不等于时长或内容量。没有实测首通时间，不承诺分钟数。
- 单活动星核、100px运输、普通石体遮力、完整特殊石构只透玩家—核力、Q只切玩家、E主动存取不变；符石只影响玩家。
- 守卫使用已有组件；不默认增加Boss、敌人种类、强制击杀开门、城镇系统、跨启动存档或大量剧情。
- 统一可通关门的门内特效；有锁的门按真实条件亮起，不能只作为装饰常亮。

## 2. 音效：先让行动与因果听得懂

### 当前核查结果

本次在活跃Godot工程中按`.wav/.ogg/.mp3/.flac`查找，未找到音频文件；脚本检索未发现已接入的`AudioStreamPlayer`播放链。现有开始菜单有Master总音量控制/持久化代码，**有音量设置不等于已有音效内容**。这不是对工程外素材库的完整盘点，不能据此说所有素材库都没有声音。

### 第一批：先补规则与危险反馈

1. **Q切相**：按下并实际切换成功时播放一次短音。辉相略温暖干脆、澜相略清冷，但不用刺耳高频；两者时长/响度接近，不让玩家误以为一相更强。图标/颜色仍为主要信息，不能只靠听觉区分。
2. **E存取与联动**：区分开罩/释放、存入锁定、脉冲到达/符石激活。锁定确认音在真实存入完成后播放，不能按E就提前报成功。将“存核→回路回应”串成短因果链，不为每帧光点加声。
3. **出口就绪**：真实不可通关→可通关时一次清楚但不刺耳的回应；失去条件有较轻的关闭声。已开启期间不循环播放确认音，入城/过关使用独立短收束音。
4. **守卫预警与接触**：举臂预警、落地攻击、有效命中、异相牵引、击散/重组三个阶段可逐步细化。预警优先级高于环境声；击中与未击中不能播成同一种“成功命中”。现组件已有`attack_started/attack_resolved/scattered_at/reassembled`等事件，可绑定真实状态，不靠每帧轮询重播。
5. **恢复/失败**：短的落空或受击反馈、恢复完成提示。失败声不羞辱、不拖长，也不要求等音效结束才恢复操作。

### 第二批：补身体感与场景质感

- 石面脚步先有走/跑节奏与轻重差别，再考虑少量变体；脚步只在真实落脚时触发，不能在空中按住方向继续响。
- 起跳/落地各自克制；轻落地不必每次震屏、重低音或大尘雾。
- 星核滚动/摩擦只在移动且接触地面时存在；低速停稳渐停，存入、暂停、恢复或切场不能留下孤立循环声。撞击设间隔限制，避免夹角抖动变成机关枪。
- 风、远处石构共鸣、门内低声作为环境层，密度低、距离衰减，不能持续盖住Q/E/守卫预警。
- F开启/翻页/收起与UI确认/返回共用少量轻音即可；残响先不做逐字打字音或角色配音。

### 混音与资源建议

- 优先顺序：危险预警/受击 > 当前交互与机关成功 > 身体动作 > 环境/音乐。先测正常音量和低音量下是否听清，不先追求声道数量。
- 分组建议为Master / SFX / Ambience / Music；当前菜单只有总音量，分组是后续技术提案，不冒充已存在独立滑块。先保持总音量/静音确实控制全部声音，再按需要扩展UI。
- 同一事件同帧只播一次；持续声最多一个实例或有限复音，离开范围/暂停/切场应停或按既定暂停行为恢复，不能叠倍。
- 素材优先自录或明确许可的免费来源。采购、收费生成、接受授权协议或上传工程均需另行同意；保存作者、原链接、许可原文和修改记录，来源未核实不能进发行包。
- 音乐最后补：先用低密度环境底与短的入城收束验证情绪，不急着做三首完整曲或守卫Boss战音乐。

## 3. 第三关灰盒布局提案

**建议初稿宽2304px，约3.6个640px视口，单向前行中有上下分路。** 以下区间用于分配职责，不是批准后的固定碰撞坐标；符石位置与落点必须按现有参数在灰盒中实测，不能为了套坐标扩大力距或跳跃。

### A｜望城与热身：x0–384

- 出生为安全地面；先看见远处城门/城墙轮廓和前路，不安排长自动演出。
- 一个宽落点的小借力动作唤回Q与跳跃记忆；不同时放星核、守卫、坠落压力和新说明。
- 用路面走势/立面开口引导方向，少量可选F内容不作为通路条件。

### B｜恢复局部通路：x384–832

- 一个短的单核运输段，源仓与关联仓之间有完整特殊石构的人核分路；不再摆四仓复习第二关。
- 用既有E入仓→记录→脉冲→符石激活。建议**把核留在这个局部仓中**，后半空手行动，不拖核经过守卫。
- 关联仓真实锁定后记录第一个稳定恢复点：玩家、唯一核所在、记录与符石状态一并保存。没有跨场景搬运第二关星核的新系统。

### C｜空手组合借力：x832–1536

- 第一个动作使用刚激活的符石登上较高路线；在可站稳的平台上给出观察下一步的机会。
- 第二个动作组合异相靠近/吸引、Q切回脱离与落点判断。必要的第二枚符石可预先激活，不额外引入“一仓多目标”控制系统。
- 两次动作要有不同的站位/落点职责，而不是复制两座相同石栅。中间安排可恢复的安全落点或下层回路，不靠看不见的空洞和极限像素边缘制造难度。
- 主核已留在B，视线/手指资源转向角色动作，形成与第二关持续盯核的节奏区别。

### D｜门前守卫：x1536–1984

- 先到一个守卫追击/攻击范围外的安全观察点，能看见举臂与落地节奏，再主动进入遭遇区。此处设置第二个稳定恢复点，失败不重做B/C。
- 只放一个现有守卫，保留有限巡逻/追击和退让空间；不叠加运核、无底坑和第二只敌人。
- **推荐通关不依赖击杀**：可引诱攻击、绕后或趁恢复窗通过；若选择交战，可临时击散，但不要求等8秒重组，不做重复刷血量。
- 重要实现事实：当前守卫`collision_layer=0`，不是实体堵门的墙。门前挑战来自攻击/牵引覆盖的路线，不应拿不可见碰撞堵住玩家，或暗加“必须清敌才亮门”。
- 可选提案：恢复已有J单次挥击组件，仅第三关使用并给一次简短安全提示。它不是现两关已有按键；**是否让J成为Demo可选动作，需要创作者确认**。无论是否启用，过门不能必须击散守卫。

### E｜跨门入城：x1984–2304

- 城门可通关时显示统一门效，守卫仍在场也不强制关门；若布局需要额外解锁，最多复用B已完成的记录条件，并显式显示其因果，不加临门第二枚钥匙。
- 角色跨过门后继续走一段可见的城内起始空间，再在内部完成区结束Demo；**不能把门洞触发与最终结算做成同一个门外瞬间**。
- 最小城内只需内侧铺地、墙体/拱影和一处明确空间变化，不做商店、居民AI或城内谜题。结算点应在城门内侧、稳定地面上，前后不会误把回退/贴门框当入城。
- 工程上可保持一张第三关场景，门的可通关反馈与城内完成区分离；正式L2完成页仅在第三关实际存在后才增加“进入第三关”，不提前跳空路径。

## 4. 制作顺序与验收门槛

1. **先确认本布局方向与J取舍**。第三关不必先画整套城墙素材；也不因本建议自动更改一二关布局。
2. **先做完整灰盒闭环**：A/B/C能走通、核局部留仓、两恢复点一致、门后实际入城、L2→L3→Demo结束流转；再在D接一只守卫。灰盒中的普通/透力材质必须有可靠区分，不能全灰到分不清规则。
3. **同步补关键音效**：先Q/E/入仓与联动/门就绪/守卫预警/失败恢复，确认事件不重播；随后补脚步和环境。声音不应成为灰盒能通关的前置依赖。
4. **再做整体美术与机制定向优化**：依据实际问题逐项改，不在没有试玩证据时一次换地形、力参数、镜头、敌人和HUD。

灰盒验收看真实行动而非地图长度：局部运输无需找隐形缝；借力不靠随机发射；每个关键跃迁看得到落点；守卫前有观察/退路，绕行可达；后段失败不重做运核；角色确实入城再结算；R/暂停/恢复/唯一核状态一致。仅检查新关键节点，完整手感由创作者试玩，不虚构试玩数据。

## 5. 后续整体美术与机制优化优先级

**先读得懂，再精致，最后扩内容。**

- 第一优先：落脚顶面、实体厚度、透力刻纹、核通道、门可通关状态、守卫预警与安全退路。重要信息要在原生1×与明亮云海背景里可读，不靠常驻大段文字救场。
- 第二优先：同族石材比例/砌缝/檐下暗部/断面内芯/柱脚接触阴影。沿用已认可完整石构，不恢复被否决的石条贴岩土拼贴，也不套一层全屏黑罩冒充光影。
- 第三优先：以第三关城墙剪影/门内拱影区分接近城区的空间，保持角色与s40残响原造型；DS03的两座大桥继续静止，不为新关破坏已有层序。
- 机制只优先修实际卡点：推拉窗口、落点可读、恢复点距离、场内脱离、守卫预警/输入冲突。优先调局部几何、提示与反馈；涉及100px、强度、角色尺寸、E/Q含义或新攻击能力的变化先明确提案与确认。
- 最后才考虑长音乐、更多装饰粒子、额外敌人和城内扩展。每次迭代保护已批准的角色/碰撞/素材来源，保留可回退版本。

### 推荐下一份制作交付

方向确认后，先交一份**第三关可玩灰盒＋门后城内完成区＋现有三关流转**，附少量新关键节点证据；美术先统一可读，不承诺最终城墙细节、成套配乐或完整发行包。若启用J，单独列明第三关限定的接入和检查范围。

## 6. 最新机制方向与素材压力评估

### 创作者新增方向

- 先通过可运输星核启动符石，借力抵达高处；高处另有固定、未激活的星核，激活后让已散落地面短暂浮起，形成必须快速通过的最后恢复通路。
- 守卫在广域引力场蓄力期间锁定极性并暴露弱点；普通阶段打碎会立即重组，只有场内有效反击才真正失活，掉落守卫核心，用于开启城门。这替换旧稿的可绕过/非强制击杀方向，不再把J列为纯可选。
- 创作者已明确选择较低容错版本：**异相吸近→切同相→顶着斥力挥击**。暂按已有移动速度/吸引获得的动量与J单挥击来实现，不默认增加冲刺键、无敌突进或速度阈值判伤。
- 后续明确为**三次有效伤害**：前两次有效命中后守卫切换极性，下一轮重新读相；第三次真正失活并掉核心。正常阶段无效击碎/重组不计有效伤害，建议也不清零已造成的真实伤害；一次挥击最多结算一次，换相不能让同一挥击重复扣血。
- 蓄力表现使用现有举臂/蓄力段循环，不循环下砸命中帧；守卫头上显示蓄力进度条。以守卫为中心播放从外向内的收缩特效，颜色始终对应守卫当前极性；蓄力期间守卫锁相。收缩表示聚能，不意味着同相玩家也会被吸引，玩家同相仍受斥力。
- 建议有效伤害同时检查真实蓄力弱点窗口、同相攻击与实际命中；同相斥力在命中前继续存在，不偷偷取消。现有挥击会快照起手相性，Q与J的先后顺序须在样段检验。
- 现守卫普通举臂预警0.28秒，不能直接当“吸近+切相+攻击”整个新循环的总时间。建议吸近阶段足够物理到达，低容错集中在最后切相与命中窗口；三次有效伤害已明确，具体窗口/场强/计时仍未验证，不在此冒充定值。

### 已实际核查的素材

- 已查看橙相守卫攻击/击散sprite sheet：已有举臂、下砸、碎裂过程；代码亦支持倒放重组。蓝/橙两套路径与主角J挥击/收招贴图存在。可用现有举臂帧短暂保持来表现灰盒蓄力，但没有专门制作的新广域蓄力动作。
- `StarCoreVisual`已有LOCKED/POSITIVE/NEGATIVE三态、16×16/12帧图；固定星核可用现图配固定底座临时代替，不能画成与运输核完全相同而误导拿取。
- 石材构建器已有薄梁/厚梁/破口块，已查看56×24破梁图；可用于浮地样段，先复用有厚度与暗底的块，不必重新画整套地面。现有图并不等于浮起/下沉、移动碰撞和失败恢复已实现。
- 现有门效/云海背景可复用；正式核心掉落物、独特城门立面/城内空间仍需最小补充或明确占位。

### 结论与限额建议

**现有素材足以支撑机制灰盒，不足以不加补充地实现最终表现；主要压力首先在新交互的工程与可读性，而不是缺整套角色动作。**

首轮只允许小范围表现补充：固定核底座/启动提示，浮地启动与将结束的预警，守卫场边界/吸斥方向/弱点/爆发分层表现。守卫掉落核心先用与普通星核形状不同的明确占位，最终另做专用图；不为验证机制重画主角、整套守卫或整张背景。现主角/Golem许可仍需对外发布前核实，内部可复用不代表已允许公开分发。

建议下一交付改为两个隔离机制样段：先验证固定核限时浮地可重试，再验证引力场锁相/同相反击/普通重组/真失活掉核；通过后重排第三关灰盒并接实际入城。浮地之后与守卫之前必须有安全缓冲和恢复点，不把倒计时与首次战斗叠成同一轮失败惩罚。样段内的场强/时序、移动平台乘坐与复位一致性，需要真实输入验证，不能仅凭现有贴图宣称支持。

### 最新确认的演出方向：电影式接管，而非半脚本F教学

创作者进一步指定RPG事件演出式呈现，覆盖此前“不夺取控制/石碑F主动交谈”的演示建议。**这只作用本段演出，平时石碑F交谈不改；尚未制作。**

1. 玩家快到仍锁定的门前，触发一次性演出；画面上下黑边，接管正常移动/跳跃/Q/J/E等玩法输入。
2. 镜头聚焦主角，角色向门前走、停住，门不动，头上出现问号。
3. 播放守卫重组声，问号改感叹号，主角回头；镜头移向守卫，展示重组及进入锁相蓄力、极性色向内收缩FX/头顶蓄力进度。
4. 镜头回到主角，同一s40残响借护符短暂显现，解释普通击碎不能损伤核心，以及异相吸近→切同相顶斥力攻击、真伤换相/共三次。
5. 演出期间玩家只用空格进行快速对话/演出跳过；结束或跳过后撤黑边、还原跟随镜头/正常输入，进入正式战斗。
