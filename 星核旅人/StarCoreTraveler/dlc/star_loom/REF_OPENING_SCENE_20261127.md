## 2. 实际看到的连续顺序

1. **0.0–2.0 s**：主角在真实石廊里向右移动；砖墙、红色垂旗、壁灯火盆、青雾和地面植被始终是实体空间。镜头跟人，没有切到黑底，也没有把房间替换成一张背景图。
2. **2.5–4.5 s**：画面进入同一关卡的 Boss 房；Boss 单独占据画面中心，主角暂时不在镜头里，顶部出现 Boss 名。约 3.0–4.5 s 有白色环形脉冲围着 Boss。房间并没有变黑，只是把注意力集中到 Boss。
3. **5.5–6.5 s**：名字淡出；Boss 的地面火焰攻击发生；主角从画面右缘进入**同一个真实房间**，镜头里同时有 Boss、主角、火焰和地面。
4. **7.0–9.5 s**：正常战斗。主角与 Boss 共用同一套房间几何与光照；Boss 的体型、颜色和攻击特效是唯一的高亮层。
5. **灯火读法**：墙面壁灯/火盆在整段里作为真实环境光源存在；Boss 房的明暗由这些固定灯火承托，而不是另画一张黑底。片段没有“顶灯逐排开关”的演出，只有真实房间常亮灯火 + Boss 聚焦 + 回到玩家。

## 3. 能借鉴

- Boss 出场先给**真实房间里的 Boss**，不是另绘一张黑底插画；房间结构、灯火和地面始终在。
- 用取景把主角暂时移出画面，让 Boss/机械独享一个短 beat；再用真实主角回到同一空间，完成「先对象、后角色」的注意力移交。
- 一个短 beat 只讲一件事：暗场轮廓 → 灯排 → 机器运转 → 核心点亮 → 回到玩家。
- 环境灯是真实空间里的固定构件（壁灯/火盆/吊灯），局部暖光贴着墙与地面，房间只做低饱和承托。
- 高饱和 / 高亮只留给机器核心与两个节点；角色回到画面后仍保持同样的玩法可读性。

## 4. 不能照搬

- 不复刻 Dead Cells 的角色、Boss、石廊、旗帜、火盆布局、配色、像素和 UI 字体。
- 不把“Boss 名条 + 环形脉冲”搬进本片；本片用真实织机、三排顶灯、两侧节点和紫色核心讲同一类“机器苏醒”的关系。
- 原片段是房间式切镜/压暗进入；本任务要求连续 Camera2D 从织机拉回入口，所以我们的横移是**按任务分镜改编**，不能写成“死亡细胞原样如此”。

## 5. 与本次实现的对应

- 真实场景：`StarLoom` 的 `CityBack`、`CityFloor`、`Boss/Core`、`Boss/NodeA`、`Boss/NodeB`、`GateFirst`、`RuneStone`、`Checkpoint`、`Player` 全部保留；开场只新增真实的 `OpeningCamera2D`、世界坐标的顶灯/节点光/核心光覆盖层，以及屏幕暗调、暗角和跳过提示。
- 镜头：0.0–2.8 s 停在真实织机厅（x≈680–692，zoom 1.14–1.20，能同时读到三排灯、链条、木梁与机体）；2.8–3.85 s 沿真实房间向左横移到 x=40 的主角，3.85–4.0 s 停在玩家玩法取景（中心 320）。拉回后半段（3.20–3.80 s）影片灯层淡出，交还时是干净的关卡取景。
- 暗调：开场用屏幕暗调把房间压暗，但从 0.0 s 起就保留真实石墙/木梁/链条的可读性，不回到黑底。
- 真实织机的梭子：直接使用本章 `loom_boss_city_208x152_4f.png` 的 4 帧，不另画第二台机器；片中把帧时钟锁到 4 fps，使 1.20–2.80 s 能稳定读到梭子从左到右。
- 参考限制：视频只用于观察「真实房间 + 对象聚焦 + 回到玩家」的关系；没有把任何帧作为运行素材。
