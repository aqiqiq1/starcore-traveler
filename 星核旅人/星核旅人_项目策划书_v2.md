# 《星核旅人》项目策划书（名称暂定）

## 1. 当前目标与约束

- 角色与世界方向：轻甲年轻探险者，探索云海之上的悬空古遗迹。
- 单人横版 2D，环境解谜与轻度平台跳跃，像素风。
- Godot 4、约一个月、四人小组、AI 辅助，交付 Windows 可独立运行 Demo。
- 三个短关卡，首次游玩目标约 10～15 分钟，以实际试玩为准。
- 面向喜欢冒险解谜的玩家，不以特定学龄教育为目标。
- 主角为本项目 `individual_sheets/male_hero-*.png` 的轻甲紫红围巾探险者；已接入并验证待机、行走、跑步、跳跃及下落，来源许可待确认。
- `基础场景原型/project.godot` 已可运行，使用 Szadi 地图和自制护符；协调者复跑200项自动断言通过，并在GUI验证默认行走、左Shift奔跑、松Shift回行走、右Shift不触发和双击奔跑。尚非完整关卡，未完成吸引排斥和星核运输；无正式玩家试玩结论。详见 `基础场景原型/功能审查.md`。

### 世界观与最小叙事

古老文明曾利用“两极之力”建造悬浮城邦。文明消失后，维系城邦的设施逐渐失效，完整的道路断裂为漂浮区块，云海间只剩庭院、回廊与沉寂的神殿。

玩家是一名穿着轻甲、系着围巾的年轻探险者，佩戴能够切换两极之力的古代护符。他深入遗迹寻找保存古代力量的星核，却发现返回的道路已经断裂，只能借助残存机关，把星核运至石座，唤醒通往外界的大门。

Demo 的目标仅是离开当前遗迹，不需要拯救世界、解释文明消失的全部真相或增加人物对话系统。能力由护符解释，通过小标识与局部光效呈现，不要求重画整套人物动画。

- 开场：短句“归路已断。借遗迹之力，寻找另一扇门。”配玩家可见的断桥。
- 过程：靠发光符文石、空石座与封闭门展示行动目标，避免长篇日志。
- 核心入座：石座与门之间的纹路依次亮起，建立开启关系。
- 结尾：出口开启，探险者走向云海中的下一段道路；用环境画面收束，不承诺额外关卡。

### 美术基调

像素风古遗迹冒险：风化石砖、残缺拱门、苔藓藤蔓、悬空平台，配少量符文微光与开阔云海。古老但不必阴暗，破碎但不追求恐怖；不采用未来空间站、机械实验室或霓虹都市作为主场景。

角色的细节密度和紫红围巾是配景基准。环境应有足够的石材层次与清楚轮廓，不使用明显过简、比例失衡的地形。背景低对比，角色、落脚点和交互物突出；围巾颜色与两种极性的标识不能混淆。

浮空与断桥优先通过布局、地形端头和远景表现，符文光效可以轻量自制，不要求一个素材包包含完整世界。允许下载免费且许可明确的候选包供审核，审核后清理本轮不合格资源；优先匹配人物风格，不因“名字叫遗迹”就认定适配，最终采用由创作者决定。

## 2. 核心玩法

观察路线与机关 → 选择自身极性和站位 → 跑跳借力或推拉核心 → 根据作用反馈调整 → 核心入槽开门 → 到达出口。

难度来自借力时机、站位、路线和行动顺序，不靠增加死亡次数或强制按键序列。允许符合规则的替代解法。

功能名与世界对应：自身极性切换＝护符切换两极之力；固定锚点＝符文石；可移动核心＝星核；插槽＝星核石座；出口＝遗迹大门。机制规格仍用功能名，避免叙事名词改变规则。

## 3. 操作与移动

- A/D 或左右方向键默认行走；按住左Shift与方向键奔跑，或0.25秒内双击同方向并按住第二次奔跑。松方向或换向取消双击奔跑；无双击锁存时松左Shift回行走，右Shift不触发。
- 空格跳跃，Q 切换自身正负极性，R 重置当前房间，Esc 暂停。暂停、重置、失焦清除连击与奔跑锁存。
- 空中可切换极性，无能量消耗；按下触发，长按不连发。
- 常规向下重力，无二段跳；受力时仍保留水平操作。
- 移动有明确加减速，提供短暂离地宽容和跳跃预输入。
- 镜头展示关键机关与落脚点，避免盲跳；房间以一至两屏为主。

## 4. 机关与交互规则

### 极性作用

- 同号相斥、异号相吸，方向沿对象中心连线。
- 固定锚点仅作用于玩家；位置和极性固定。
- 玩家与可移动核心相互作用，双方都有对应反应，玩家可用移动抵抗。
- 每房间最多一个核心；不计算锚点—核心或核心—核心作用。
- 有限作用范围，边缘连续减弱；实体地形阻断中心连线后不作用。
- 近距离强度、速度设上限，避免中心重叠引发爆速或穿透。
- 两种状态用不同符号与辅助颜色区分；有效范围和方向反馈与实际作用同步。
- 箭头表示极性作用方向，不是最终速度方向；重力与输入仍然存在。
- 属于游戏化规则，不承诺精确物理模拟。

### 核心、插槽与出口

- 核心受重力、地形碰撞和阻尼，不能拾取、投掷或装入背包；主要通过极性作用运输，不依赖身体顶推。
- 运输路线优先连续地面；玩家可以通过侧路换位，不要求核心悬空过坑。
- 核心在插槽中低速稳定停留后锁定，出口保持开启；玩家走入出口才完成关卡。
- 插槽不要求正负匹配，不检查是否经历极性转换。
- 锁定后核心停止受力；重置房间恢复核心、插槽与门。
- 核心极性转换机关不纳入当前必做主线。

### 危险与重置

- 仅做落坑和一种静态危险表面，优先石刺或轮廓清楚的遗迹尖刺；不增加移动机关或周期伤害规则。
- 不设生命次数、生命条或硬性倒计时；失败后快速恢复操作。
- 玩家失败、核心丢失、手动 R 均恢复当前房间的完整初始状态：位置、速度、极性、机关、插槽、门及临时反馈。
- 检查点位于房间入口，已完成房间进度保留；核心不能带入上一房间。
- 任意误操作都应能在游戏内恢复，不依赖退出程序。

## 5. 三关功能结构

1. **断桥庭院／基础借力：** 在开阔的遗迹入口学习移动与切换，利用符文石分别体验吸引、排斥并跨越断桥；无核心任务，抵达出口通关。
2. **沉寂回廊／核心运输：** 星核与封闭门建立任务目标，安全平地练习推拉，再通过侧路换站位，将核心送入石座开门；避免一路推就绕过全部空间问题。
3. **云顶圣所／组合挑战：** 核心位于连续地面通道，玩家侧路包含符文石借力跨越；组合临时停放、绕行换位和运输，入座开门后走向云海出口。

三关共用一套主地形，以空间布局、装饰密度与远景区分。所有布局需验证可达性、运输稳定性及容错，不能把概念描述当成已验证地图；不要求核心飞过断崖。

## 6. 流程、界面与反馈

- 主菜单 → 开始/选关 → 三关 → 最终结算 → 主菜单。
- 选关为三个简单按钮，默认均可进入，便于课程演示；直接进入后提供必要操作提示。
- HUD 显示当前目标、极性与 Q/R 提示，不使用知识评分。
- 暂停包含继续、重置房间、重开本关、操作、音乐/音效音量与静音、返回菜单。
- 结算显示完成、用时、重置次数及下一关/重玩/返回；暂停不计时，失败和手动重置避免重复计数。
- 本次启动内记录进度与设置，跨启动存档可选。建议窗口失焦自动暂停。
- 必要反馈包括跳跃、极性切换、入槽/开门、失败；音乐可选，不依赖声音传达唯一线索。

## 7. 素材与技术要求

- 像素风，以现有轻甲人物为参考，优先寻找匹配的古遗迹地图，其次星核物品/特效；允许少量免费候选下载审核，淘汰后清理，不批量囤积。
- 主角现有待机、走路、跑步、跳跃、下落与下落循环；暂不另找角色，也不因素材中含攻击动作而新增战斗。
- 优先主地形一套、背景一套、符文石/星核/石座/遗迹门基础造型、中文字体；机关可简单自制，不先收集多种主题。
- 人物动画表均为透明 PNG、每帧 128×128；实际身体远小于帧画布，跑步可见高度约 33～36 像素。角色与地形比例按可见身体比较，保留统一帧画布，碰撞体不包含围巾和留白。
- 逻辑画面可从 640×360、16 像素地形网格起测，不作为硬性选材限制；最终统一比例，最近邻采样、整数倍缩放。
- 主素材在首测试房检查角色脚底、透明边缘、动画、地形拼接和碰撞，再扩关卡。
- 核查作者原链、适用许可、修改/游戏分发/源工程共享权限、署名要求；不使用来源不明资源，不未经批准购买或注册。
- 使用 Godot 原生能力与 GDScript，固定物理步长，参数集中可调；不开发超出三关需要的大框架。
- 暂停冻结场景、计时与触发；重置清理旧事件，切关清理节点、信号和统计残留。
- 如需 Python，使用 `D:\minic\envs\2024212971`。

## 8. 制作组织与排期

- 默认一个开发智能体实现，负责人管理设计、集成和验收；其他成员分别协助关卡、素材许可、测试打包。
- 第一周：匹配环境主素材并核实人物许可，完成借力与运输测试房；不成立先修，不铺三关。
- 第二周：三关可通，菜单到结算全流程完成，首次 Windows 导出。
- 第三周：统一表现、必要音效、少量非开发者试玩，优先修可读性、手感和卡关。
- 第四周：冻结新玩法、修缺陷、异机测试；第 26 天形成候选包，留缓冲。
- 不做战斗、敌人 AI、移动陷阱、追逐、背包、技能树、联网、零重力、飞船驾驶、多核心或复杂剧情。
- 润色可缩减；核心玩法、三关和交付要求如需变更须另行确认。

## 9. 验收与交付

- 作用方向正确，范围/遮挡/符号/箭头一致，近距离不爆速。
- 核心可控、稳定入槽开门，所有失败和重置恢复可解状态。
- 三关能从头通至结算；直接选关、暂停、重开和返回菜单正常。
- 试玩记录实际理解与操作问题，不虚构好评、时长或效果。
- 在未安装 Godot 的另一台 Windows 电脑验证解压启动、输入、声音、中文与完整流程。
- 交付可执行文件及必要资源、README、署名许可、真实测试记录；源工程保留备份，是否提交按教师要求及许可决定。

## 10. 当前下一步

先试玩 `基础场景原型`，确认人物比例、基础移动手感和逐帧护符贴合；确认后再制作锚点吸引/排斥与单核心运输测试。环境与星核候选已审查，不扩大素材检索；对外发布前补齐角色授权。
