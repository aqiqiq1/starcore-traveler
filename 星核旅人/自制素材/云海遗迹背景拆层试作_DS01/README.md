## 2. 拆层与补洞做法

**提取的像素**（全部来自 V7，不重画轮廓）：天空云 14,136 px；云海远层 18,071 px；云海近层 36,218 px；中央浮石 768 px；左下浮石组 260 px；小碎屑 57 px；低处浮石 522 px。云海只分远/近两层：两层在浅色带与深色带的交界处互相遮挡，需要不同速度；再拆更多层不会增加可读性。

**天空云的画外余量**：原 640 宽天空层的画内像素和 alpha 原样保留；左右各加的 12px 是 x=0 / x=639 边缘列的水平延续（同样的 alpha 和色带），只用于横移时接住画面边缘。它不缩放、不模糊、不重绘画内云，也不进入 V7 调色板之外的颜色。原图 x=0 的交界在 dx=+6 时位于屏内 x=6，但交界两侧逐像素相同，所以看不到硬切线；右边缘同理。

**补绘只发生在原位被遮住的区域**：
- 天空云移走后，底图用原 V5/V6 的纵向天空渐变补齐；云层 alpha 逐像素，不夹带天空矩形。
- 云海移走后，底图在桥体范围内用 V6 桥体几何 + V7 的八档雾化公式重建（隐藏桥像素 3,282 px）；非桥区域用天空/浅云色补。桥柱、桥面、远岛、院落、云中残拱均留在静态底，不随云移动。
- 低处浮石在云海前方，遮挡的是云。它下面的 522 px 云用同行左右最近的云色补回（中点分界），保证浮石轻浮时原位露出的是云而不是洞或天空。补绘色全部来自 V7 调色板。
- 中央浮石/浮石组移走后，底图只用同行左右最近的天空色填充；不做插值、模糊或锐化。
- 输出统计：所有 PNG 层/底图的可见 RGB 都是 V7 已有颜色的子集，未新增 RGB 值；见 `checks/palette_check.json`。

**静态保留、不当作碎岩移动**：桥梁/柱、左侧带塔和院落的浮岛、右侧带小殿的浮岛、两处云中残拱、桥柱旁贴着断柱的小石片、右侧很淡的远石台。这样避免把建筑误拆成浮石。

`preview_background.gif`：640×360，72 个时间步 × 90 ms = 6.48 s，无限循环；GIF 写入器把相邻的完全相同的整数像素状态合并并加倍时长，所以文件内实际存储 58 帧，总时长仍为 6.48 s。

## 5. 已知问题 / 未验证

- 低处浮石下的云是同行最近色重建，不是唯一真实的原始像素；±1 px 小位移下未见洞/双影，2× 压力下可能出现一块偏平的云色或中点分界。需要更高保真时应在有原始分层源文件时重做。
- 天空云的画外 12px 是边缘列的直线延续，不是重新绘制的画外云；批准范围 ±6 内只露出 6px，看起来是云带继续出画，但没有新的云形变化，也不是无限云卷图。2× 压力位移（12px）时延续区几乎不露出，原边界正好落在视口边缘。
- 两处云中残拱留在静态底；云海移动会以 2–4 px 幅度盖住/露出它们的基部。这是当前“云在前”的近似，不是完整的半沉遮挡模拟。
- 云海 656 宽夹边在画面最边缘会有一点“云被边缘固定”的感觉；没有露白边，但不等同于无限云图。
- 浮石只拆了 4 组明确对象；右侧很淡的远石台和贴断柱小石片保持静态。如果它们也要动，需要另一次明确授权，不应顺手扩大范围。
- GIF 为全局 256 色、无抖动；PNG 层为全 RGB。GIF 只用于看动效，不是最终运行素材。
- 未接 Godot、未做视差/性能/分辨率适配、未做实机试玩；未改玩法，也未对“整体美术优于其他模型”下结论。
- 静态 0 差异不等于动效通过；下一步应由协调者/美术负责人决定是否接受此拆分，再考虑引擎内试叠。
